# 로지스틱 회귀 vs 룰 기반 위험도(v3) — 정직한 비교 (결정 기록)

**한 줄 요약**: "위험도를 룰 점수표(v3) 대신 로지스틱 회귀로 갈아탈 가치가 있는가?" 를 **실측으로** 답했다.
결론은 **(B) — 지금 표본으로는 회귀가 룰을 못 이긴다. 룰 기반(v3)을 유지하는 것이 옳다.**
전체 8룰(관측 가능한 7개) 회귀는 교차검증에서 룰 v3 에 **유의하게 진다**(짝지은 부트스트랩 ΔAUC −0.052, 95%CI [−0.102, −0.010]).
EPV 를 지킨 3피처 간소 모델조차 룰과 **비기거나 진다**(ΔAUC −0.038, CI [−0.075, −0.007]). 게다가 회귀는 **음의 계수**(WAVE_HIGH, NEARBY_LOW = "파도/저밀도가 강할수록 덜 위험")를 뱉는데, 안전 서비스에 그대로 못 쓴다.

- 재현 스크립트: [`../scripts/logistic-compare.ts`](../scripts/logistic-compare.ts)
- 데이터: 백테스트 덤프(`backtest-result.json`)를 그대로 읽는다 — 데이터 로딩을 재구현하지 않았다. 근거·표본: [`backtest.md`](./backtest.md), 룰 v3: [`risk-rules-v3.md`](./risk-rules-v3.md)
- 실행일: 2026-07-15
- ⚠️ **이 작업의 가치는 "회귀 써봤다"가 아니라 "써야 하는지 정직하게 판단했다"에 있다.** 회귀가 졌으므로 졌다고 쓴다.

## 0. 방법 — 무엇을 어떻게 쟀나

- **데이터 재사용**: 백테스트(`backtest-risk.ts`)가 이미 만든 `units`(주 × 시군구 136단위)를 읽는다.
  각 단위에 룰 발화값(NEARBY 밀도, TEMP_UP, TEMP_7D_AVG, WAVE_HIGH, WIND_INFLOW, PAST_OCCURRENCE)과 정답(밀도)이 들어 있다.
  NIFS 파싱·기상청 관측 로딩을 재구현하지 않았다(스크립트에 도메인 import 조차 없다 — 전부 덤프에서 나온다).
- **타깃**: `density==='high'` (고밀도 = danger 이상). **룰 v3 의 대표 AUC(0.886)와 같은 타깃**이라 사과 대 사과다.
- **피처 7개**: NEARBY_HIGH, NEARBY_LOW, TEMP_UP, TEMP_7D_AVG, WAVE_HIGH, WIND_INFLOW, PAST_OCCURRENCE.
  CURRENT_INFLOW(전 기간 결측)·BEACH_VULNERABILITY(전 단위 상수 → 절편이 흡수)는 제외.
- **모델**: 로지스틱 회귀를 **경사하강법으로 직접 구현**(수십 줄). **새 npm 의존성 없음.**
  **L2 릿지** 포함(절편은 정규화 안 함), 강도 λ 는 CV 로 선택. 피처는 학습 표본 통계로 표준화(누수 방지).
- **검증(핵심)**:
  - **그룹 5-겹 교차검증** — 같은 주의 두 시군구가 학습/검증으로 갈리지 않게 **주(week) 단위 블록**으로 폴드를 나눈다. NEARBY 가 '직전 주'를 참조해 인접 주가 상관되므로 시군구·주 누수를 이렇게 막는다.
  - **룰 v3 도 같은 폴드에서** 평가(룰은 학습이 없어 고정 점수 → 같은 검증 폴드에서 AUC). 사과 대 사과.
  - **짝지은 부트스트랩 3000회**(out-of-fold 예측) 로 회귀−룰 ΔAUC 의 95%CI. 0 을 넘는지가 "유의하게 이기는가"의 판정.
  - **시간 분할**(2024~2025 학습 / 2026 홀드아웃) — n=20(고밀도 3)이라 **참고용**, CV 를 주 지표로.

EPV(events per variable) = 26 양성 / 7 피처 = **3.7**. 통상 하한 10 을 크게 밑돈다 → 7피처는 구조적으로 과적합 위험.

## 1. 교차검증 결과 — 회귀 vs 룰 v3

| 모델 | in-sample AUC | **CV AUC(평균±SD)** | OOF AUC | 과적합 격차<sup>†</sup> | 시간분할 2026<sup>‡</sup> |
|---|---|---|---|---|---|
| **룰 v3 (기준선, 학습 없음)** | 0.886 | **0.873 ± 0.146** | 0.886 | ~0 (학습 없음) | 0.990 |
| 회귀 7피처 λ=0 (정규화 없음) | 0.919 | 0.803 ± 0.208 | 0.851 | **0.116** | — |
| **회귀 7피처 λ=0.30 (CV 최적)** | 0.883 | 0.835 ± 0.167 | 0.835 | 0.048 | 0.892 |
| 회귀 7피처 λ=3.0 (과정규화) | 0.872 | 0.826 ± 0.178 | 0.651 | 0.046 | — |
| 간소 2피처 (NEARBY_HIGH+TEMP_UP) | 0.878 | 0.860 ± 0.136 | 0.844 | 0.018 | — |
| **간소 3피처 (NEARBY_HIGH+LOW+TEMP_UP)** | 0.888 | **0.884 ± 0.134** | 0.849 | **0.004** | — |

<sup>†</sup> 과적합 격차 = in-sample AUC − CV AUC. 클수록 계수를 데이터에 맞춘 것. **λ=0 에서 0.116** 이 정규화 없는 회귀가 왜 폭주하는지 보여준다(표본이 작아 계수가 훈련 표본에 과하게 붙는다).
<sup>‡</sup> 2026 홀드아웃 n=20(고밀도 3). **신뢰구간이 표 전체를 덮는다 — 순위를 논할 수준이 아니다.** 참고로만 싣는다. (여기서도 룰 0.990 > 회귀 0.892 지만 표본 때문에 의미 없다.)

### 유의성 — 회귀가 룰을 이기는가? (짝지은 부트스트랩, OOF)

```
회귀 7피처(λ=0.30) − 룰 v3 : ΔAUC −0.052  95%CI [−0.102, −0.010]  ← 0 미포함, 전부 음수. 룰이 유의하게 낫다.
간소 3피처         − 룰 v3 : ΔAUC −0.038  95%CI [−0.075, −0.007]  ← 0 미포함, 전부 음수. 룰이 유의하게 낫다.
```

**어느 회귀 모델도 룰 v3 를 이기지 못한다.** 전체피처 회귀는 CV 에서 오히려 유의하게 진다.
간소 3피처 모델은 **per-fold CV 평균(0.884)만 보면 룰(0.873)과 비슷**하지만(SD 가 크게 겹친다), 폴드마다 다른 모델을 합쳐 하나로 재는 **OOF 로 재면 0.849 로 내려가 룰(0.886)에 유의하게 진다.** 즉 회귀의 in-sample 우위(0.888)는 검증에서 **증발**하고, 룰은 학습이 없어 0.886 을 그대로 유지한다. **이게 "in-sample 로 이기는 건 의미 없다"의 실측이다.**

## 2. 회귀 계수 — 무엇이 위험한가

전체 표본 학습, λ=0.30, **표준화 계수**(크기 비교 가능). 부트스트랩은 **주 단위 그룹 리샘플 3000회**.

| 피처 | 계수 | 부호 | 부트스트랩 95%CI | 부호 뒤집힘 | 판정 |
|---|---|---|---|---|---|
| **NEARBY_HIGH** | **+0.521** | + | [+0.37, +0.64] | 0.0% | ✅ 지배 신호. 안정적·해석 가능 |
| NEARBY_LOW | **−0.013** | **−** | [−0.13, +0.10] | 40.5% | ⚠️ **음수** — "저밀도일수록 덜 위험". 부호가 40% 뒤집힘 = 무신호 |
| **TEMP_UP** | +0.175 | + | [+0.05, +0.29] | 0.4% | ✅ 2차 신호. 안정적·양수 |
| TEMP_7D_AVG | +0.125 | + | [−0.01, +0.25] | 3.3% | ⚠️ CI 가 0 포함 — 방향 불확실 |
| **WAVE_HIGH** | **−0.056** | **−** | [−0.15, +0.04] | 11.9% | ⚠️ **음수** — "파도 높을수록 덜 위험". 안전 서비스에 못 쓴다 |
| WIND_INFLOW | +0.003 | + | [−0.10, +0.12] | 49.3% | ⚠️ 사실상 0, 부호 동전던지기 |
| PAST_OCCURRENCE | +0.023 | + | [−0.11, +0.16] | 34.1% | ⚠️ CI 가 0 포함 — 무신호 |

절편 b = −1.576.

**위험한 계수(음수 = "이 신호가 강할수록 덜 위험"): WAVE_HIGH, NEARBY_LOW.**
- WAVE_HIGH −0.056 은 백테스트 과제 D 에서 이미 관찰된 **역방향 리프트(0.67)** 와 일치한다 — 파고는 고밀도 주에 오히려 덜 켜진다. 회귀는 이 잡음을 **음의 계수로 그대로 학습**한다. 룰 v3 는 이걸 5점(양수 하한)으로 묶어 예보 연동만 살려두고 방향은 뒤집지 않는다 — **룰이 안전하게 처리하는 걸 회귀는 위험하게 처리한다.**
- NEARBY_LOW −0.013 은 부호가 40% 뒤집히는 **무신호**다. 저밀도는 "고밀도의 약한 신호"가 아니라 방향이 다르다는 v3 문서의 관찰(리프트 0.73)을 재확인한다.

**해석 가능하고 안정적인 계수는 NEARBY_HIGH, TEMP_UP 둘뿐**이다. 나머지 5개는 CI 가 0 을 포함하거나 음수다.
26개 양성으로 뽑은 계수는 이만큼 불안정하다. **회귀가 스스로 "믿을 건 NEARBY 와 수온뿐"이라고 말하고 있다** — 그건 룰 v3 가 이미 큰 가중치(NEARBY 40, TEMP_UP 15)를 준 바로 그 두 룰이다.

## 3. 하이브리드 — 중간안은 값이 있나

NEARBY(밀도)는 압도적 신호(리프트 19)라 룰로 고정하고, **약한 관측 피처의 상대 가중치만** 회귀로 정하는 중간안을 검토했다.

```
관측 피처만 회귀 (NEARBY 제외, 5피처)   CV AUC 0.688 ± 0.147   OOF 0.609   ← 관측만으로는 약하다
NEARBY 밀도등급 단독 (고2/저1/없음0)     in-sample AUC 0.880           ← 이거 하나가 룰 전체(0.886)와 거의 같다
하이브리드 (NEARBY 등급 + 관측회귀 보정)  OOF AUC 0.867                 ← NEARBY 단독을 못 넘는다
```

**하이브리드도 값이 없다.** NEARBY 밀도등급 단독(0.880)이 이미 룰 전체 성능의 거의 전부다. 관측 회귀 보정을 얹어도 OOF 0.867 로 **오히려 내려간다**(관측 피처의 잡음이 순위를 흔든다). 이는 백테스트가 이미 말한 것과 같다 — **신호의 대부분이 NEARBY 밀도에서 나오고, 나머지 관측 룰은 희석 요인**이다. 회귀로 그 상대 가중치를 "최적화"해봐야 잡음을 학습할 뿐이다.

## 4. 최종 판정 — (B) 룰 유지가 옳다

세 질문에 데이터로 답한다:

1. **교차검증 AUC 에서 회귀가 룰 v3 를 유의하게 이기는가?** → **아니다.**
   전체피처 회귀는 유의하게 **진다**(ΔAUC −0.052, CI [−0.102, −0.010]). 간소 3피처도 진다(−0.038, CI [−0.075, −0.007]).
   가장 잘 봐줘도 per-fold CV 평균에서 룰과 **비기는** 수준이고, 이기는 구간은 없다.

2. **회귀 계수가 해석 가능하고 안전한가?** → **아니다.**
   음의 계수 2개(WAVE_HIGH, NEARBY_LOW). 7개 중 안정적 양수는 2개(NEARBY_HIGH, TEMP_UP)뿐.
   정규화 없으면(λ=0) in-sample 0.919 로 폭주하고 CV 는 0.803 으로 무너진다(격차 0.116).

3. **26개 양성으로 8피처 회귀가 과적합하는가?** → **그렇다.**
   λ=0 격차 0.116. λ 를 CV 로 골라도(0.30) 격차 0.048 이 남는다. 피처를 3개로 줄이면 격차는 0.004 로 사라지지만,
   그 순간 모델은 "NEARBY + 수온"이 되어 **룰 v3 와 사실상 같은 것**이 된다(그리고 여전히 룰을 못 이긴다).

**→ 결론 (B): 회귀가 룰과 비슷하거나 나쁘다. 표본 부족(양성 26)과 과적합이 원인이다. 룰 기반(v3) 유지가 옳다.**

### 왜 이런 결과인가 (정직하게)

- 룰 v3 는 사실상 **이미 잘 조율된 모델**이다. 지배항(NEARBY 밀도)이 일을 다 하고, 약한 관측 룰은 안전한 하한(5점)으로 묶여 있다. 회귀에게 남은 자유도는 "약한 신호들의 상대 가중치"뿐인데, 그 신호들은 **진짜로 신호가 없어서**(WAVE 역방향, WIND/PAST 무신호) 회귀가 최적화할 게 없다.
- 회귀의 계수는 오히려 **룰 v3 의 설계를 검증**한다: NEARBY_HIGH ≫ TEMP_UP > 나머지. 룰이 손으로 준 순서(40, 15, 5)를 회귀가 데이터로 재발견한다 — 다만 더 큰 분산과 위험한 부호를 얹어서. **갈아탈 이유가 아니라 현 룰을 유지할 근거다.**

## 5. 지금은 판단 못 하는 부분 / 무엇이 더 있어야 하나

이 판정은 **"현재 표본에서 회귀가 룰을 못 이긴다"** 까지다. 다음은 **여전히 미결**이다(부분적으로 (C)):

1. **표본이 회귀에 근본적으로 부족하다.** 양성 26개로는 어떤 회귀도 5개 이상 피처를 안정적으로 학습 못 한다.
   회귀가 룰을 넘을 가능성을 **공정하게** 보려면 **양성(고밀도 주×시군구) 최소 ~80개**(EPV 10 × 8피처)가 필요하다.
   지금 연 ~26 양성 속도면 **3~4개 시즌(2028~2029)** 더 쌓여야 한다. 그 전엔 회귀 재검토가 무의미하다.
2. **정답이 시군구 단위다.** 회귀든 룰이든 해변 내부 변별력(협재 vs 함덕)은 검증 불가. 회귀가 이걸 풀려면 **해변 단위 정답**(안전요원 기록·현장 관찰)이 필요하다 — 데이터 종류 자체가 다르다.
3. **1~4월·제보 룰·CURRENT_INFLOW 미검증**은 백테스트와 동일한 한계로 회귀에도 그대로 적용된다.
4. **더 풍부한 피처**(연속값 수온·파고·유향, 종별 밀도, 특보 리드타임)가 생기면 회귀의 자유도가 늘어 재평가 가치가 생긴다. 지금은 룰이 쓰는 이진 발화값만 있어 회귀와 룰의 입력이 사실상 동일하다.

## 6. (참고) 만약 통합한다면 — 조건과 방법

**현 판정은 통합하지 않는 것이다.** 아래는 위 §5 의 조건(양성 ~80개 + 연속 피처)이 갖춰졌을 때를 위한 설계 메모일 뿐, **지금 실행 권고가 아니다.** 통합 여부는 사용자·팀이 결정한다.

- **어디에 얹나**: 엔진(`RiskEngine.calculate`)을 갈아엎지 말 것. 회귀가 이긴다는 증거가 생겨도, **NEARBY 는 룰로 두고 관측 항의 가중치만 회귀가 정하는 하이브리드**가 현실적이다(전부-회귀는 계수 폭주·해석 실패 위험).
- **`ml_models` 테이블 활용**(이미 존재): `algorithm='logistic_l2'`, `hyperparams_json`={lambda, 표준화 μ/σ, 계수}, `metrics_json`={cvAuc, oofAuc, ci}, `model_status` training→staging→active→archived, `RiskScore.modelId` 로 산출-모델 링크. **계수·λ 를 DB 에 실어 재현·롤백 가능하게** 한다(현 룰의 `risk_rule_configs` 와 같은 거버넌스).
- **안전 가드(필수)**: 음의 계수/폭주를 **배포 전에 차단**한다 — 단조성 제약(모든 위험 신호 계수 ≥ 0) 또는 배포 게이트("음의 계수가 나오면 승격 금지"). 안전 서비스라 회귀에게 "파도 높을수록 덜 위험"을 절대 허용하면 안 된다.
- **재학습 주기**: NIFS 주간보고는 5~12월 주간 갱신 → **시즌 종료 후(연 1회) 재학습**이 적절. 상시 재학습은 표본이 작아 오히려 계수가 흔들린다.
- **거버넌스**: 새 모델은 항상 **staging 에서 이 문서의 CV+짝지은 부트스트랩으로 현행(룰 or 직전 모델)과 대조** → 유의하게 이길 때만 active 승격. 못 이기면 룰 유지. 판정 자동화 스크립트 = `logistic-compare.ts` 를 그대로 재사용.
