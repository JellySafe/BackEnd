# 운영 비용 정리 (Fly.io + Aiven)

> 기준일: 2026-07-14 · 실제 배포 환경(`jellysafe-be-rosieoh`)과 운영 DB를 직접 조회해 작성했다.

## 요약

| 시나리오 | 월 비용 |
|---|---|
| Aiven **Free** 플랜인 경우 | **약 $3~4** (Fly 만) |
| Aiven **유료** 플랜인 경우 | **약 $55~65** ← 현재 사용량 대비 과하다. Free 로 내릴 것 |

경진대회/MVP 규모에서 현재 아키텍처로 비용 문제가 생길 여지는 없다.
유일한 시한폭탄이던 "데이터 무한 적재"는 보관정책으로 막아뒀다(아래 참고).

## Fly.io — 월 $3~4

실측한 현재 설정:

| 항목 | 설정 | 비용(대략) |
|---|---|---|
| 머신 | `shared-cpu-1x` / **512MB** / 도쿄(nrt) / **24시간 상시** | 월 $3 안팎 |
| 볼륨 | `jellysafe_uploads` 1GB (제보 사진) | 월 $0.15 |
| 트래픽 | 사실상 없음 | ~$0 |

### 상시 실행을 끌 수 없는 이유

`fly.toml` 이 `min_machines_running = 1`, `auto_stop_machines = 'off'` 다. 의도적이다.

- 30분마다: 외부 데이터 수집 → 관측소 매핑 → 위험도 재산출
- 새벽: 보관정책 파기 배치 4종 (관측 03:20 / 제보 03:30 / 위험도 03:40 / 알림 03:50)
- 매일: 일간 리포트 생성

`auto_stop` 을 켜면 요청이 없을 때 머신이 자고, **배치가 아예 돌지 않는다.**
즉 상시 실행 비용은 배치 서비스의 필수 비용이다.

또한 **머신을 2대 이상으로 늘리면 안 된다.** 크론이 머신마다 돌아 위험도가 중복 산출되고,
사진 볼륨은 머신 한 대에만 붙으며, 레이트 리밋 카운터도 머신별 인메모리다.
확장이 필요해지면 볼륨 → 오브젝트 스토리지, 레이트 리밋 → 공유 저장소, 배치 → 단일 워커 분리가 선행돼야 한다.

### 메모리를 256MB 로 낮추면?

컨테이너 실측: **512MB 중 약 150MB 사용**(MemTotal 459MB / MemAvailable 313MB).
낮추면 월 $1.5 정도 아낀다. **그러나 권장하지 않는다.**

국립수산과학원 주간보고 **PDF(1.4MB)를 파싱**할 때 메모리가 순간적으로 튄다.
256MB 에서 OOM 으로 죽으면 수집 배치가 멈추고, 해파리 데이터가 조용히 말라간다.
$1.5 를 아끼려고 감수할 위험이 아니다.

### 주의

**Fly.io 는 무료 티어를 폐지했다.** 예전 문서를 보고 "무료겠지" 하고 넘기면 안 된다.
실제 청구액은 [fly.io/dashboard](https://fly.io/dashboard) → Billing 에서 확인한다.

## Aiven — 사용량은 무시할 수준, 플랜만 확인하면 된다

### 현재 사용량 (실측)

- MySQL **8.4.8**
- **DB 총 사용량: 3.8 MB**

| 테이블 | 크기 | 행 수 |
|---|---|---|
| risk_factors | 1.86 MB | 8,322 |
| risk_scores | 0.48 MB | 3,024 |
| observations | 0.13 MB | 729 |
| jellyfish_reports | 0.13 MB | 17 |
| notifications | 0.09 MB | 35 |

### 보관정책 적용 후 안정 상태 (추정)

행당 실측 크기를 기준으로 계산했다. 보관 기간이 지나면 파기되므로 **이 선에서 더 늘지 않는다.**

| 테이블 | 보관 | 안정 상태 |
|---|---|---|
| risk_factors | 90일 | ~100 MB |
| risk_scores | 90일 | ~25 MB |
| observations | 30일 | ~4 MB |
| **합계** | | **약 150 MB** |

Aiven 무료 플랜 한도가 5GB 이므로 **약 30배 여유**가 있다.

보관정책이 없었다면 위험도만 시간당 3회씩(스케줄러 2개가 중복 산출) 쌓여 1~2년 내 한도에 닿았을 것이다.
배경은 커밋 `FIX: 위험도 재산출 중복 실행 제거 + 산출 이력 보관정책 도입` 에 적어뒀다.

### 확인 필요 — 유일한 비용 리스크

**Aiven 콘솔에서 이 서비스의 플랜이 `Free` 인지 확인할 것.**
DB 내부에서는 플랜을 알 수 없다.

- `Free` 플랜 → **$0**
- `Startup` 등 유료 플랜 → **월 $50~60**. 현재 사용량(3.8MB)에 비하면 완전히 과하므로 Free 로 내린다.

## 비용에 영향을 주는 설계 결정 (요약)

| 결정 | 비용 영향 | 이유 |
|---|---|---|
| 머신 1대 상시 실행 | 비용의 대부분 | 배치(수집·산출·파기)가 돌아야 한다 |
| 메모리 512MB 유지 | +$1.5/월 | PDF 파싱 시 메모리 스파이크. OOM 시 수집 중단 |
| 위험도 재산출 30분 1회로 단일화 | DB 증가율 1/1.5 | 이전엔 시간당 3회(스케줄러 2개가 중복) |
| 보관정책(위험도 90일 / 관측 30일 / 알림 90일) | DB 상한 확보 | 없으면 무한 증가 |
| 사진을 볼륨에 저장 | +$0.15/월 | 컨테이너 FS 는 재배포마다 소실된다 |

## 비용 확인 방법

```bash
# Fly 머신 사양·상시 실행 여부
fly machines list --app jellysafe-be-rosieoh
fly volumes list --app jellysafe-be-rosieoh

# 실제 청구액
fly dashboard   # → Billing
```

```sql
-- Aiven DB 사용량
SELECT ROUND(SUM(data_length + index_length) / 1024 / 1024, 1) AS mb
FROM information_schema.tables
WHERE table_schema = DATABASE();
```
