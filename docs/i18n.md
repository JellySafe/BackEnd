# 다국어 — 무엇을 번역했고, 무엇을 하지 않았나

> 공개 API 표시 문구의 언어 지원. **범위를 분명히 하는 것이 이 문서의 목적이다.**
> 반쯤 번역된 화면을 다 된 것처럼 두면, 못 읽는 사람이 읽을 수 있다고 착각하게 만든다.

---

## 왜 하나

제주는 외국인 방문객이 많고, **해파리 쏘임은 말이 안 통할 때 가장 위험한** 종류의 사고다.
위험 단계와 "지금 무엇을 해야 하는가" 를 못 읽으면 이 서비스는 그 사람에게 없는 것이나 같다.

## 지원 언어

`ko`(기본) · `en` · `zh` · `ja`

`zh` 는 **간체**다. 번체 사용자에게도 간체가 나가는데, 아무것도 못 읽는 것보다 낫다고 보고
택했다. 별도 번체 카탈로그는 두지 않았다.

## 언어를 고르는 방법

```
?lang=en                     ← 우선
Accept-Language: en-US,en;q=0.9
(둘 다 없거나 지원 밖이면)     → ko
```

`?lang=` 을 함께 받는 이유 — 앱에는 **기기 언어와 별개로 언어를 고르는 화면**이 흔하다
(한국에 오래 산 외국인은 기기가 한국어일 수 있다). 브라우저에서 바로 확인할 수단이 있으면
문제를 찾기도 훨씬 쉽다.

**모르는 값은 거부하지 않고 한국어로 되돌아간다.** 표시 언어 하나 때문에 안전 정보 조회를
400 으로 막을 이유가 없다. 두 공개 엔드포인트가 같게 동작한다.

---

## ✅ 번역되는 것

| 무엇 | 어디 | 개수 |
|---|---|---|
| **위험 단계 라벨** | `riskLevelLabel`, `maxRiskLabel`, `from/toLabel` | 4 |
| **안전 안내 문구** | `guideText` | 4 |
| **위험 요인 이름** | `factors[].name` | 15 |
| 산출 이력 없음 표시 | `riskLevelLabel`, `maxRiskLabel` | 1 |

적용 엔드포인트: `GET /public/beaches/:id/risk`, `GET /public/daily-report`

세 가지가 함께 있어야 의미가 있다 — **무엇인지**(단계), **무엇을 해야 하는지**(안내),
**왜 그런지**(요인). 단계만 번역하면 "Danger" 를 읽고도 무엇을 할지 모른다.

## ❌ 번역되지 않는 것 (그리고 이유)

| 무엇 | 왜 |
|---|---|
| 해변 이름 | **DB 콘텐츠.** 번역 컬럼과 운영 절차가 함께 있어야 한다 |
| 해파리 종 정보(이름·독성 설명) | 같음. 게다가 **오역이 안전에 직결**되는 내용이라 검수 주체가 필요하다 |
| 알림 문자·푸시 문구 | 같음. 받는 사람의 언어를 서버가 들고 있지 않다(수집하면 개인정보가 는다) |
| 운영기관 공개 코멘트 | **사람이 쓴 글**이다. 기계 번역하지 않는다 |
| `factors[].detail` | 수치를 섞어 **조립하는 문장**이라 언어마다 어순이 다르다 |
| 관리자 API·오류 메시지 | 운영자는 한국어를 쓴다. 시민 화면과 대상이 다르다 |

이 목록은 "나중에 하겠다" 가 아니라 **지금 안 되는 것을 적어 둔 것**이다. 프론트가 화면을
그릴 때 어느 필드가 한국어로 올지 알아야 레이아웃과 안내를 맞출 수 있다.

---

## 캐시 — 여기가 가장 조용히 틀린다

공개 조회 응답은 캐시된다(`PUBLIC_CACHE_TTL_SECONDS`, 기본 30초). 캐시 키가 URL 뿐이면
**먼저 채워진 언어가 다른 언어 요청에 그대로 나간다.** 오류도 나지 않는다.

`?lang=` 은 URL 에 있어 저절로 갈리지만 **`Accept-Language` 는 그렇지 않다.** 그래서 키에
해석된 언어를 넣는다.

```
키 = "{언어}|{URL}"
```

헤더 **원문**이 아니라 **해석 결과**를 쓰는 것도 중요하다. `ko-KR,ko;q=0.9` 와 `ko` 는 다른
문자열이지만 같은 한국어다 — 원문을 키로 쓰면 브라우저마다 헤더가 조금씩 달라 캐시가 사실상
동작하지 않는다.

---

## 번역할 때 지킨 것

- **약속하지 않는다.** 어느 언어에서도 `safe` 를 '안전'/'Safe' 로 쓰지 않는다. 그건 쏘이지
  않는다는 **보장**으로 읽히는데, 우리가 아는 것은 위험 신호가 낮다는 것뿐이다.
  → `낮음` / `Low` / `低` / `低`
- **행동을 남긴다.** 모든 언어의 안내 문구에 "무엇을 하라" 가 들어간다. 상태 설명만 남으면
  읽는 사람이 판단을 떠안는다.
- **현장 지시를 우선하게 한다.** 서버가 아는 것보다 현장 안전요원이 아는 것이 늘 정확하다.
- **빈 문자열을 내보내지 않는다.** 번역이 비면 한국어로 되돌린다. 라벨 자리가 비면 화면에서
  위험 정보가 통째로 사라진 것처럼 보이는데, 그건 번역이 없는 것보다 나쁘다.

## 요인 이름은 코드로 다시 찾는다

`risk_factors.factor_name` 에는 **산출 시점의 한국어가 굳어 있다.** 그 값을 그대로 쓰면 언어를
바꿀 수 없으므로, 함께 저장된 `factor_code` 로 카탈로그를 다시 찾는다. 카탈로그에 없는
코드(옛 데이터, 사라진 룰)면 저장돼 있던 이름으로 되돌아간다 — 이름 없는 항목을 남기지 않는다.

## 언어를 더하려면

`SUPPORTED_LOCALES` 에 코드를 넣으면 **모든 카탈로그가 컴파일 오류로 빠진 곳을 알려준다**
(`LocaleText` 가 전 언어를 필수로 강제한다). 조용히 빠지는 언어가 생기지 않는다.

카탈로그 위치: `shared/kernel/risk-level.ts`(단계 라벨),
`contexts/risk/domain/risk-guide.ts`(안내 문구), `contexts/risk/domain/risk-factors.ts`(요인 이름).
