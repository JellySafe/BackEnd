# 위험도 점수표 v3 — 결정 기록 (NEARBY_ALERT 를 밀도 기반으로)

**한 줄 요약**: `NEARBY_ALERT` 가 출현 **건수**만 세고 밀도를 무시하던 문제를 고쳤다. 창 안 **최고 밀도**로
등급을 매겨 고밀도 40 / 저밀도 5 로 준다. 그 결과 운영에서 **제주 12개 해변이 전부 danger** 로 나오던 상태가 풀렸다 —
danger 판정 비율 41.2% → 19.9%(성수기 59.7% → 37.5%), 고밀도 vs 저밀도 AUC 0.704 → **0.827**, 고밀도 놓침은 2건 그대로.
danger 컷오프는 **45 를 유지**했다(밀도 반영 후 재검증). 저밀도 지역이 '안전'으로 침묵하지 않도록 **최소 '주의' 보장(MIN_NEARBY_1)** 을 새로 넣었다.

- 코드: `risk-factors.ts`(밀도 코드), `risk-assessment.ts`(밀도 선택·문구·최소단계), `risk-input.kysely-query.ts`(`findNearbyAlert`)

## 0. 문제 — 건수는 위험의 강도가 아니다

운영에서 제주 12개 해변이 **전부 danger** 로 나왔고 점수 구성이 사실상 같았다.

```
협재(제주시, 고밀도 2종)   65점 = NEARBY 40 + 나머지 25
표선(서귀포시, 저밀도 1종) 70점 = NEARBY 40 + 나머지 30   ← 저밀도가 더 위험하다고 말한다
```

NIFS 원본은 밀도를 구분해 발표한다(제주시 high / 서귀포시 low). 우리는 이미 `jellyfish_occurrences.density_level` 로
파싱해 저장하고 있었는데, 위험도 산출의 `countNearbyAlerts` 는 **건수만 세고(`COUNT(*)`) 밀도를 안 봤다.**

**핵심 통찰**: 그 '건수'는 위험의 강도가 아니라 **NIFS 주간보고에 그 시군구가 몇 종으로 적혔는가**의 부산물이다.
주간보고는 `종 × 시군구` 마다 한 행을 만든다(`nifs-report.parser.ts`). '제주시 3건' = 해파리가 세 배 많다가 아니라
**세 종으로 적혔다**는 뜻이다. 종 하나가 초대량 출현한 주가 더 위험할 수 있다. 백테스트가 이를 정면으로 확인한다:

```
직전주 경보건수별 → 이번주 고밀도 비율        직전주 밀도별 → 이번주 고밀도 비율
  0건: 112단위 → 7.1%                        none:  80단위 →  3.8%
  1건:  20단위 → 70.0%                        low :  34단위 → 14.7%
  2건:   2단위 → 100%                         high:  22단위 → 81.8%   ← 밀도가 신호다
```

단일 신호 비교(과제 A, AUC): **직전주 밀도등급 0.880** > 직전주 경보건수 0.823 > 직전주 경보등급 0.821.
룰별 리프트(과제 D): **NEARBY_ALERT_HIGH 리프트 19.04**(고밀도 주 69.2% 발화 / 그 외 3.6%), 단일 AUC 0.828, p<0.001.
반면 NEARBY_ALERT_LOW 리프트 0.73(고밀도 주에 오히려 덜 켜진다) — **저밀도는 '고밀도의 약한 신호'가 아니라 방향이 다르다.**

## 1. 무엇을 바꿨나

| | v2 (건수) | **v3 (밀도)** |
|---|---|---|
| 입력 | `nearbyAlertCount: number` (경보성 출현 건수) | `NearbyAlertInput` (최고 밀도 + 종 + 시군구) |
| 쿼리 | `countNearbyAlerts` — `COUNT(*)`, `alert_level IN (attention,caution,warning)` | `findNearbyAlert` — 밀도 행을 뽑아 **최고 밀도** 선택 |
| 발화 룰 | `NEARBY_ALERT` (단일, +40) | `NEARBY_ALERT_HIGH`(40) / `_MEDIUM`(15) / `_LOW`(5) |
| 문구 | "인근 해역 속보 3건" | "제주시 고밀도 출현(노무라입깃해파리, 유령해파리류)" |
| 저밀도 침묵 방지 | (없음) | **MIN_NEARBY_1** — 인근 출현 확인 시 최소 '주의' |
| 컷오프 | danger 45 | danger 45 (**유지** — 재검증) |

**최고 밀도 vs 합산 — 최고 밀도를 쓴다.** 합산하면 건수 방식의 병이 그대로 돌아온다(종 3개면 3배). 종 개수는
그 해역 해파리의 양과 무관하다. "그 해역의 최악 상태가 무엇인가"가 위험도가 답할 질문이고, 그건 최댓값이다.
합산을 흉내 낸 후보 (g)(종수 보너스)를 백테스트했지만 이득이 없었다(§2).

**`alert_level` 필터를 뺐다.** 옛 쿼리는 `alert_level IN (attention,caution,warning)` 로 걸렀는데, `alert_level` 은
`resolveAlertLevel(NIFS 특보단계, 밀도)` 의 합성값이라 **특보가 없는 주의 저밀도 출현은 'none'** 이 되어 통째로 버려졌다.
NIFS 특보는 광역 행정 조치라 관측보다 늦거나 아예 안 나온다. 관측 사실을 행정 절차가 검열하게 두는 셈이라, 밀도가 기록된
출현은 **특보 유무와 무관하게** 근거로 삼는다(대신 저밀도 점수를 낮게 준다). 특보 게이트를 유지한 후보 (d)와 비교했다(§2).

## 3. 최종 결정과 근거

### 왜 고밀도 40 / 저밀도 5 인가

- **고밀도 40**: v2 의 `NEARBY_ALERT` 무게(40)를 그대로 물려받는다. 고25(b2)로 내리면 danger 재현율 73.1% → 61.5%
  로 떨어지고 부트스트랩 ΔAUC CI[+0.003,+0.047]로 유의하게 나빠진다. 45+ 로 올리면 severe 가 튄다(v2 §4 와 동일 산수).
- **저밀도 5**: 저밀도를 스윕(0/5/10/15/20)했다. 성능은 저5·저10 이 서로 구별되지 않는다(부트스트랩 CI 0 포함).
  갈림은 **변별력**이다 — 저10(b3)은 저밀도→danger 비율이 15.4% → **25.6%** 로 뛴다. 저밀도가 다시 고밀도처럼
  취급되기 시작한다. **저5 는 저밀도가 단독으로 어떤 단계도 못 만들면서**(5+취약도5=10=안전) 성능 손해가 없는 값이다.
  저0(e)까지 내리면 고밀도 놓침이 2 → 4건으로 는다(저밀도 지속성이 이번주 고밀도의 약한 예보이기도 하다). → **5**.
- **중밀도 15**: NIFS 주간보고엔 없는 등급(고/저 2단계)이라 **표본에 없다 = 검증 못 했다.** 고와 저의 중간값으로 뒀다.
  제보·mock 수집기가 넣을 수 있어 사다리를 비우지 않았을 뿐, 이 값은 근거 없는 잠정치다.

### 왜 danger 컷오프 45 를 유지하나

v2 문서(§4)는 "밀도 반영 없이 danger 56 → 45" 를 최고 값의 후속 작업으로 꼽았고, 그건 이미 배포됐다(현행 45).
밀도를 반영한 **뒤에** 다시 쟀다(과제 E-1 그리드 390조합, E-2 컷오프 스윕). 45 가 F2·변별력 균형의 최적이다:
56 으로 올리면(c) 오경보율은 0% 지만 재현율 73.1% → 57.7% 로 손해고 변별력(고vs저 AUC 0.827) 이득이 없다.
**→ `risk-level.ts` 를 바꿀 필요가 없다.** 시드 `LEVEL_*` 도 v2 와 동일(45/76)로 그대로 맞춰 뒀다.

### 왜 최소 '주의' 보장(MIN_NEARBY_1)을 넣었나 — 안전 서비스의 비용 비대칭

밀도 점수를 도입하면 저밀도 지역 점수가 확 낮아진다(의도한 것). 부작용으로 **"NIFS 가 저밀도 출현을 확인했고
예비주의보까지 발령 중인데 화면엔 '안전'"** 이 생긴다. 실제 최근 주 재현에서 표선·신양섭지가 그랬다. 안전 서비스가
할 말이 아니다 — 과제 지시대로 **쏘임 사고를 놓치는 비용 > 헛경보 비용**이다.

점수만으로는 못 고친다. 저밀도 점수를 caution 바닥(31)까지 올리면 여름 수온이 얹혀 곧장 danger 로 튄다(저밀도→danger
비율 폭증). **바닥과 점수를 분리**해야 한다 — 그게 RISK-002 최소 단계 보장의 존재 이유다. `deriveNearbyMinTriggers` 가
인근 출현 확인 시(밀도 무관) 최소 '주의'를 깐다.

이 트리거는 **danger 를 만들지 않는다**(caution 바닥일 뿐). 그래서 (i)와 (b)는 danger 지표·변별력이 **완전히 동일**하고,
저밀도 출현 주가 '안전' 대신 '주의'로 올라오는 것만 다르다. 대가: caution 오경보(출현 없는 주에 주의) 22.7% → 38.2%.
**caution 은 '모니터링 강화'라 공개 경보도 입수 통제도 아니다.** danger(빨강)는 19.9% 로 그대로 희소하다 —
"늘 빨간색이면 아무도 안 믿는다"는 danger 에 걸린 문제고, 그건 안 건드렸다. F1 하나로 뭉뚱그리지 않고
danger(균형)·caution(재현율 그물)·severe(정밀도)를 각각 봤다.

### 적용 후 예상 — 제주시(고밀도) vs 서귀포시(저밀도)가 실제로 갈린다

최근 주(2026-07-09 산출, 입력=직전 보고 2026-07-02: 제주시 high / 서귀포시 low + 예비주의보) 재현:

```
해변            시군구    직전밀도   v2(건수)      →  v3 채택(밀도)
협재            제주시    high      50점 위험    →  50점 위험     ← 갈린다
함덕            제주시    high      65점 위험    →  65점 위험
중문색달        서귀포시   low       65점 위험    →  30점 주의     ← 위험에서 주의로
표선            서귀포시   low       50점 위험    →  15점 주의     ← 최소주의 보장(점수만이면 안전)
화순금모래       서귀포시   low       70점 위험    →  35점 주의
신양섭지        서귀포시   low       50점 위험    →  15점 주의
```

**제주시 고밀도 해변 = 위험, 서귀포시 저밀도 해변 = 주의.** 사용자가 "어느 해변이 그나마 안전한가"에 답을 얻는다.
(주의: 위 관측 요인은 PAST_OCCURRENCE·TEMP_UP·취약도이고, 인근 밀도 점수는 그 위에 얹힌다. 저밀도가 '주의'인 것은
MIN_NEARBY_1 이 깐 바닥이다 — 점수만이면 15점=안전이었다.)

교차표(채택안, 136단위):
```
           없음  저밀도  고밀도
  safe       54     14      2
  caution    15     19      5
  danger      2      5     15
  severe      0      1      4     ← severe 5건(3.7%), 그중 실제 고밀도 80% (NIFS 특보 발표율 4.4% 와 눈금 일치)
```

## 4. 롤백

`RISK_RULE_VERSION=v1` 또는 `=v2` 로 되돌리면 된다. DB 는 세 버전이 다 들어 있다(seed 가 v1·v2·v3 나란히 심는다).

- **점수 롤백은 완전하다.** 도메인이 v3 부터 밀도별 코드(`NEARBY_ALERT_HIGH/MEDIUM/LOW`)로 발화하므로,
  v1·v2 시드에도 그 세 코드를 넣어 뒀다(v1=전부 15, v2=전부 40 = 각 버전의 밀도 무구분 동작 재현). 이게 없으면
  옛 버전이 폴백(15)으로 거짓 롤백된다.
- ⚠️ **한 가지 드리프트**: 최소 '주의' 보장(`deriveNearbyMinTriggers`)은 도메인 로직이라 버전과 무관하게 항상 작동한다.
  v2 는 인근 출현 점수가 40 이라 이미 caution+ 이므로 **무영향**. v1(인근 15+취약도5=20)은 present-occurrence 주가
  '안전'→'주의'로 올라온다. v1 은 이미 "쓰지 마라(재현율 처참)"로 문서화된 깊은 롤백이고, 이 드리프트는 더 안전한
  방향이라 코드 버전 게이팅(env 값을 도메인에 주입) 대신 이 문서에 명시하는 쪽을 택했다.

**환경변수 (배포자가 넣어야 함)**: `RISK_RULE_VERSION=v3`
재산출 강제: `POST /system/risk/calculate`.

## 5. ★ 이 v3 를 어디까지 믿어도 되는가 (정직하게)

### 믿어도 되는 것
- **방향**: 밀도가 건수보다 강한 신호다. 리프트 19.0 vs 건수 기반 — 자릿수가 다르고, 부트스트랩 ΔAUC CI[+0.020,+0.111]가
  0 을 포함하지 않는다. "밀도로 바꿔야 한다"는 표본을 흔들어도 안 뒤집힌다.
- **변별력이 실제로 생겼다**: 고 vs 저 AUC 0.704 → 0.827. danger 판정 비율 41.2% → 19.9%. 이건 이번 개정의 목적이었고 달성됐다.
- **저밀도는 고밀도의 약한 버전이 아니다**: 저밀도 리프트 0.73(역방향). 저5 가 저10 보다 변별력에서 낫다.

### 믿으면 안 되는 것
1. **전부 in-sample 이다.** 같은 136개 표본에서 밀도 점수(고40/저5)와 컷오프(45)를 골랐다. **"AUC 0.886"을 성능
   보증으로 인용하지 마라.** 2026 홀드아웃(n=20, 고밀도 3)은 AUC 0.98 이 나왔지만 표본이 20개라 신뢰구간이 표 전체를 덮는다. 참고 불가.
2. **중밀도(15)는 완전한 잠정치다.** NIFS 주간보고는 고/저 2단계뿐이라 medium 이 표본에 **0건**이다. 검증한 적이 없다.
   제보·mock 이 medium 을 넣기 시작하면 재평가하라.
3. **해변 *내부* 변별력은 여전히 검증 불가.** 정답이 시군구 단위(제주시/서귀포시)라 협재 vs 함덕을 가릴 수 없다.
   이번 개정이 검증한 변별력은 **시군구 간**이다. 같은 시군구 안 해변들은 여전히 관측(수온·풍향)으로만 갈린다.
4. **최소 '주의' 보장의 점수는 검증 못 했다.** MIN_NEARBY_1 은 danger 지표를 안 바꾸므로 백테스트의 고밀도 탐지 성능에
   영향이 없다 = **백테스트가 이 결정을 검증하지 못한다.** "저밀도 출현 중 침묵은 안 된다"는 안전 서비스의 **가치 판단**이지
   측정 결과가 아니다. caution 오경보 38.2% 가 사용자 화면에 얼마나 시끄러운지에 따라 이 판단은 뒤집힐 수 있다
   (뒤집으려면 후보 (b) — MIN_NEARBY_1 제거 — 로 가면 danger 성능은 그대로다).
5. **`alert_level` 필터를 뺀 결정도 in-sample.** 특보 게이트 유지(d)와 제거(i)의 ΔAUC CI 가 0 을 포함한다 —
   "게이트를 빼도 나빠지지 않는다"까지가 주장이고, "빼서 좋아졌다"가 아니다. 저밀도 저점수라 게이트 없이도 과경보가 안 났을 뿐이다.
6. **1~4월 미검증, 제보 룰 미검증, CURRENT_INFLOW 전 기간 결측** — v2 §7 의 한계가 그대로 유효하다.
7. **종수 보너스(g)를 안 쓴 건 "이득 없음" 이지 "해로움" 이 아니다.** ΔAUC CI 가 0 을 포함한다. 건수를 다시 넣을 이유가 없어서 뺐다.

### 못 한 것
- 실제 프로덕션 DB 재산출로 12개 해변 최종 화면을 확인하지 못했다(운영 DB 시드 금지 — 배포자가 돌린다). §3 의 재현은
  백테스트 엔진 출력이지 프로덕션 파이프라인 전 구간(예보 연동·신뢰도·알림)을 통과한 값이 아니다.
